### S8. 제2장. QData 솔루션 | 1. QData 개요
- 핵심 메시지(헤드라인): 흩어진 데이터를 AI가 바로 쓰는 데이터로, QData는 네 개의 기둥으로 연결합니다

- 본문:
  - 정의: 정형·비정형·시계열·문서 데이터를 연결하고, RAG·CAG·TAG 기반 AI가 바로 활용할 수 있는 데이터로 가공하는 AI-Ready Data Platform

| 기둥 | 소제목 | 핵심 |
|---|---|---|
| 파이프라인 | 수집부터 활용까지 한 흐름으로 | 표준 커넥터 연결, 통신 단절 시 엣지 임시 저장으로 유실 방지 |

- 근거: 정의 SRC §2 정의 / 4대 기둥·소제목 SRC §2 4대 기둥 표(v2 소제목 — SRC §1 차이표 3행) / 적합 조직 SRC §2 Ideal Use Cases

### S9. 제2장. QData 솔루션 | 2. 전체 구성도
- 핵심 메시지(헤드라인): 데이터 원천에서 활용 서비스까지, 하나의 플랫폼 안에서 5개 계층이 이어집니다
- 부제: Data Sources → Core Pipeline → AI Data Engine → AI-Ready Data Outputs → AI Applications
- 본문 — 구성도 명세(3열 + 하단 띠 2단):

| 영역 | 구성 |
|---|---|
| ① 데이터 원천(좌, 범주별 묶음) | 정형 — ERP·MES·DB·CSV·API / 비정형 — PDF·DOCX·PPT·메일 / 산업 — PLC·센서·시계열·영상 / 지식 — 매뉴얼·리포트·표준·이력 |
| 원천 → 플랫폼 화살표 라벨 | 표준 커넥터 · 산업 표준 프로토콜(OPC-UA · MQTT·Sparkplug B · Modbus) |
| ② QData 플랫폼(중앙) — 수집·연계 | 표준 커넥터 연결 · 통신 단절 시 엣지 임시 저장 |
| ② — Core Pipeline | Connect → Parse → Clean → Standardize → Contextualize → Ready (세로 6칸, S10) |
| ② — AI Data Engine | RAG Ready(검색·근거): †질의 해석 → 문서 벡터 검색 → 근거 문맥 제공 / CAG Ready(반복 참조 컨텍스트 최적화): †지식 캐시 적재·갱신 → 캐시 매칭·호출 → 캐시 문맥 제공 / TAG Ready(탐색·집계용 구조): †조건·집계 해석 → 테이블·DB 질의 → 계산 결과 제공 (S12) |
| ② — AI-Ready 산출물 | Knowledge Data · Context Data · Structured AI Data · Training Data (S12) |
| ③ 활용 서비스(우) | LLM·sLLM(상용 API·온프레미스 소형) / AI 에이전트(근거 붙여 답하고 실행까지) / 예측 모델(이상 감지·수요·품질) / Cubeon(판단을 승인과 업무 실행으로) — 대시보드·실시간 조회, QFactory·AgentQ가 활용 |
| 하단 띠 1 | 데이터·모델 운영(품질·변경 이력 확인, 변화 시 재학습·검증 후 반영) · 거버넌스(카탈로그·계보·폴더 단위 권한·감사 로그) · 표준(OPC-UA · ISA-95 · MQTT·Sparkplug B · Modbus) |
| 하단 띠 2(최하단) | 온프레미스·폐쇄망 구성 — 망분리 요건 대응 |

  - 데모 화면 예시: 재학습 트리거 드리프트 지수 임계 1.0 — 현재 설비 이상 감지 모델 0.7
- 시각 요소 제안: 가로 3열 구성도 — 좌 원천 4묶음(점선 테두리 그룹) → 화살표 2개(라벨: 표준 커넥터 / 산업 표준 프로토콜) → 중앙 플랫폼 큰 박스 안 4칸[수집·연계 | Core Pipeline 세로 6칸 | AI Data Engine(RAG·CAG·TAG 박스 각 3단계) | 산출물 4종] → 우 활용 서비스 4칸. 플랫폼 아래 가로 띠 2단(운영·거버넌스·표준 / 온프레미스·폐쇄망). 기존 제안 도식의 세로 오케스트레이터 띠는 QData 원문에 없어 두지 않음.
  - [캡처: 개요 — 5계층 아키텍처 도식(계층 클릭 이동)과 KPI 6종(커넥터 11개 · 일 수집량 3,120만 건 · 데이터셋 48개 · 태그 표준 매핑 94.8% · 엣지 버퍼 유실 0건 · 품질 규칙 위반 3건)]
  - [캡처: 05 데이터·모델 운영 › 모델 성능·재학습 — 설비 이상 감지·수요·품질 예측 모델 성능 추이와 드리프트 표, 재학습 이력]
  - [캡처: 06 활용 › 서비스 연계 — LLM·sLLM · AI 에이전트(AgentQ) · 예측 모델 · Cubeon 4카드와 각 카드가 쓰는 산출물 표시]
- 근거: 5계층·원천 4범주·엔진 정의·산출물·활용 서비스 SRC §2 Architecture 1~5 / QFactory·AgentQ SRC §2 Overview / 엣지 임시 저장·재학습 SRC §2 4대 기둥 / 거버넌스·표준 칩 SRC §2 Standards & Governance(칩은 v2 — SRC §1 차이표 5행) / 폴더 단위 권한 SRC §2 Features Governance / 폐쇄망·망분리 SRC §2 Ideal Use Cases ④ / 데모 STD §5
- 근거(기존 제안): 오큐브 기존 제안(REB 발표자료 S22) — 3열 전체 구성도 레이아웃(원천 → 플랫폼 → 서비스 + 하단 운영 띠 + 최하단 인프라 띠), RAG·CAG·TAG 각 3단계 풀이(†) — QData 적용 여부 확인 필요
- 발표 멘트: 왼쪽의 데이터가 가운데 플랫폼을 거쳐 오른쪽 AI 서비스로 갑니다. 아래 띠의 운영·거버넌스·표준과 폐쇄망 구성이 이 흐름 전체를 받칩니다.

### S10. 제2장. QData 솔루션 | 3. 6단계 코어 파이프라인
- 핵심 메시지(헤드라인): 모든 데이터는 같은 6단계를 거쳐 품질·일관성·맥락을 갖춥니다
- 부제: Connect · Parse · Clean · Standardize · Contextualize · Ready
- 본문:

| 단계 | 원문 정의 | 데모 화면 예시(샘플 사업장, 금일 누적) |
|---|---|---|
| Connect | 연결 — 표준 커넥터, 통신 단절 시 엣지 임시 저장 | 커넥터 11개(정상 10 · 주의 1), 수집 3,120만 건 |
| Parse | 구조화 — 표·도면 섞인 문서 정리, OCR·STT | 문서 1,248건 구조화(OCR 212 · STT 18) |
| Clean | 품질관리 — 중복 제거 · 오류 보정 · 결측 처리 | 중복 제거 0.4% · 결측 보정 1.8%(임계 3.0%) · 오류값 보정 1,920건 |
| Standardize | 스키마 통일 · 단위 표준화 | 태그 8,420개 중 7,986개 표준 매핑(94.8%) · 미매핑 434개 · 단위 변환 규칙 36종 |
| Contextualize | 도메인·업무 맥락과 관계 | 관계 1,640개 · 용어 사전 1,280개 |
| Ready | 품질 · 일관성 · 맥락 | AI-Ready 데이터셋 48개 갱신 · 품질 점수 평균 92 |

  - 엣지 임시 저장 데모 예시: 엣지 게이트웨이 3대 · 금일 통신 단절 2회(최장 7분 12초) · 버퍼 재전송 18,420건 · **유실 0건**
- 시각 요소 제안: 6칸 가로 화살표(단계명 + 원문 정의) + 칸마다 데모 수치 1개. 우하단에 엣지 임시 저장 박스(단절 → 버퍼 → 재전송 → 유실 0).
  - [캡처: 02 코어 파이프라인 › 6단계 파이프라인 — 6단계 보드(3,120만 건 · 1,248건 · 1,920건 보정 · 7,986 태그 · 1,640 관계 · 48 데이터셋)와 데이터셋별 진행 단계]
  - [캡처: 01 수집·연계 › 데이터 소스·커넥터 — 엣지 게이트웨이 GW-01~03, 금일 단절 2회 · 최장 7분 12초 · 재전송 18,420건 · 유실 0건]
- 근거: 단계명·정의 SRC §2 Architecture 2(Connect·Parse 보충은 SRC §2 4대 기둥 파이프라인·비정형 처리) / 데모 수치 STD §1·§2
- 발표 멘트: 데이터 종류와 관계없이 같은 6단계를 거치므로, 어느 단계에서 무엇이 걸렸는지 추적할 수 있습니다. 적용 모습은 제3장 4절에서 보여드립니다.

### S11. 제2장. QData 솔루션 | 4. 비정형 문서 처리
- 핵심 메시지(헤드라인): 표·도면이 섞인 문서와 이미지·음성까지 AI가 읽을 수 있는 구조로 바꿉니다
- 부제: Parse 단계 상세 — 구조화 · OCR·STT · 검색 단위 점검 · 실패 문서 재처리 · 개인정보 처리
- 본문:
  - 좌 — 문서 처리 흐름(원문 기능):

| 순서 | 처리 | 원문 기능 |
|---|---|---|
| 1 | 구조화 — 표·도면 섞인 문서를 의미 단위로 정리, 이미지는 OCR·음성은 STT | 4대 기둥 '비정형 처리' |
| 2 | 처리 현황 추적 — 단계별 상태 · 변경 감지(신규·업데이트·삭제 자동 반영) · 개인정보 표시 | Pipeline |
| 3 | 검색 단위 최적화 — 품질 지표(길이·특수문자·중복·의미 완결성) · 문서별 진단(주의·경고) · 분할 규칙 | Chunking |
| 4 | 실패 문서 재처리 — 실패 단계 기록 → 자동 재처리(재시도·우선순위 큐) / 수동 처리 분기(담당자 통보) | Recovery |
| 5 | 개인정보 마스킹 · 반영 상태 확인(청크 수·처리 상태) | Governance |

  - 데모 화면 예시: 문서 1,248건 구조화(OCR 212 · STT 18)
  - 우 — 파싱 품질 확보 방식(†, 기존 제안 구조):
    - 2단계 파싱: 경량 모델로 레이아웃 영역 분할·1차 보정 → 고성능 모델로 영역 단위 정밀 보정 → 표·목록·제목 등 영역 유형별 구조화 출력
    - 저품질 문서 유형 분류·보정: 워터마크 · 회전 · 구겨짐 · 기울임
    - 사용자 검수: 추출 위치 하이라이트 → 사용자 확인·수정 후 저장 → 개인정보 자동 탐지·비식별화(원문 '개인정보 마스킹'과 대응)
    - 모델 평가 2단계: 범용 벤치마크 → 자체 벤치마크 → 서비스 적용 → 사용자 피드백
- 시각 요소 제안: 좌 번호 배지 5단 흐름 + 문서 처리 화면 캡처 / 우 2단계 파싱 화살표(경량 → 고성능) + 저품질 유형 칩 4개 + 하단 평가 2단계 띠. 기존 제안 도식의 '좌 서비스 화면·번호 기능 / 우 품질 확보 방식' 2단 레이아웃 재사용. 우측 † 영역은 연한 배경으로 구분.
  - [캡처: 02 코어 파이프라인 › 문서 처리 파이프라인 — 처리 현황 탭(단계별 상태·변경 감지)과 재처리 탭(실패 단계·재시도 큐)]
  - [캡처: 02 코어 파이프라인 › 6단계 파이프라인 — 데이터셋별 진행 중 '점검일지 스캔'(OCR 판독 중)·'회의·교대 음성 기록'(STT 변환 중)]
- 근거: 구조화·OCR·STT SRC §2 4대 기둥 비정형 처리 / 처리 현황·검색 단위·재처리·마스킹 SRC §2 Features(Pipeline·Chunking·Recovery·Governance) / 데모 STD §2
- 근거(기존 제안): 오큐브 기존 제안(REB 발표자료 S26) — 2단계 파싱(경량→고성능), 저품질 유형 분류·보정, 추출 위치 하이라이트·사용자 수정, 개인정보 자동 탐지·비식별화 흐름, 벤치마크 2단계 적용 절차(†) — QData 적용 여부 확인 필요
- 발표 멘트: 문서는 형식이 제각각이라 그대로는 AI가 읽지 못합니다. 구조화하고, 검색 단위를 점검하고, 실패한 문서는 다시 처리하는 흐름을 한 곳에서 관리합니다.
